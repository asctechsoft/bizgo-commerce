## Endpoint-level rule set (tested by generated matrix test)

- Audience prefixes: `/v1/admin/**` ⇒ realm `ADMIN`; `/v1/factory/**` ⇒ realm `FACTORY` and `factory_id` scope; `/v1/me/**` ⇒ realm `CUSTOMER`; `/v1/**` public ⇒ none. A token from the wrong realm ⇒ 401/403 before any DB access.
- Resource predicate injected in repositories; out-of-scope id ⇒ **404** (customer A→customer B order; org A→org B tier; factory A→factory B job).
- Field-level: DTO allowlists per audience (ADR-0008); `pii:read` unmasks phone/email/address; `cost:read`/`margin:read` gate finance fields in admin DTOs (ADR-0010).
- State-level: permission **and** transition guard (e.g., `order:cancel` allowed only in cancellable states).
- Forbidden attempts: logged (`FORBIDDEN_ACCESS`, rate-sampled) with actor, route, resource type — no PII.

## Open design points flagged for owner UAT

1. Can FACTORY_STAFF accept/reject jobs, or only FACTORY_MANAGER? (Matrix default: manager only; staff pick/pack/handover.)
2. Should SALES_CS see tier prices beyond `lim`? (Default: view tier price, cannot change cost; discounts bounded by `lim`.)
3. WAREHOUSE role vs FACTORY_MANAGER for inventory counts — both allowed within assignment; D03 decides the real org structure.
