## How blocked decisions appear in code

1. Each is a feature flag or a `settings` key that **defaults to the safe value** and is validated at startup (`config/feature-flags.ts`).
2. Every blocker has a stable API error code (e.g. `PRICE_NOT_SET`, `DELIVERY_UNSUPPORTED`, `OTP_DELIVERY_NOT_CONFIGURED`) so UI shows an honest Vietnamese message instead of a fake success.
3. Tests tagged `@blocked(Dxx)` assert the fail-closed behaviour; when the owner answers, the tag and ADR are updated together.
