# ADR-0012 — Media, private files, personal data

**Status:** Proposed · **Sources:** Spec §02/§11, Arch §10, BRD §11 · **Blocked:** D09, D10, D11

- **Two buckets:** `bizgo-public-catalog` (CDN, immutable keys by content hash, image variants generated by worker with `sharp`) and `bizgo-private` (packaging evidence, return photos, compliance docs, wholesale documents) — no public ACL; access only by short-lived signed URLs minted after a scope check.
- **Uploads:** `POST /v1/files/presign` with `purpose` ∈ `RETURN_EVIDENCE | PACKING_EVIDENCE | COMPLIANCE_DOC | WHOLESALE_DOC | PRODUCT_MEDIA | TICKET_ATTACHMENT`; server enforces MIME allow-list per purpose (images: jpeg/png/webp; docs: pdf), size caps, `Content-Length`/checksum, and records `file_objects(owner_scope, purpose, sha256, size, status PENDING|SCANNED|REJECTED)`. Object is unusable until a worker scan (magic-byte check + ClamAV hook if available) marks it `SCANNED`.
- **Product imagery truth:** `product_media.is_illustrative` for AI images (labelled "Ảnh minh họa" in UI) vs `verified_at` for real photos; verified media is a publish-gate item (ADR-0009).
- **Personal data:** collect only what the flow needs; consent records in `user_consents(purpose, version, accepted_at, ip_hash)`; PII fields masked in admin lists unless `pii:read`; logs never contain OTP/tokens/passwords or full addresses; redaction (not delete) for financial records; retention periods and account-deletion workflow are **placeholders** until D09 (feature flag `ACCOUNT_DELETION_ENABLED=false`, request is still recorded as a support ticket).
- **Secrets:** only via environment/secret store; `.env.example` has dummy values; CI secret scan (gitleaks) and `detect-private-key` hook; no VPS IP in clients.
