# ADR-0011 — Frontend architecture, design system, i18n, responsive/a11y

**Status:** Proposed · **Sources:** Spec §10, route matrix, prototype `source/BizGo_Responsive_Web_Demo/` · User rule: UI Vietnamese, code English, extensible localisation

## Decision

- **Next.js App Router + TypeScript strict + Tailwind.** Public pages are **Server Components** fetching the API server-side (SEO, no client waterfall); interactive parts are small Client Components. Data layer: generated client from `packages/contracts` + TanStack Query for client mutations/cache. **No fallback to fixtures when the API fails** — show error state with retry. Mock fixtures only behind `NEXT_PUBLIC_DEMO_FIXTURES=true`, forbidden in production builds (build-time check).
- **Design tokens** (from prototype, mapped to Tailwind theme + CSS variables in `packages/ui-web/tokens.css`): green `#176a3a`, deep `#104b2a`, mint `#e9f7ed`, soft `#f5f8f4`, ink `#1c2c24`, muted `#718077`, border `#e3ebe4`, orange `#f67829`, radius 18, shadow `0 12px 40px #184b2c12`, container 1240, Be Vietnam Pro via `next/font`. Component set rebuilt semantically: `Header, SearchBox, CategoryNav, MobileNav/BottomBar, Hero(Slider), BenefitStrip, CategoryCard, ProductCard, PriceBlock, QtyStepper, FilterDrawer, Breadcrumb, Table, FormField, Modal/Drawer (focus-trapped), Toast, Skeleton, EmptyState, ErrorState`.
- **Routes:** per `docs/ui_route_api_matrix.csv` (Vietnamese slugs, e.g. `/danh-muc`, `/san-pham/[slug]`, `/gio-hang`, `/thanh-toan`, `/tai-khoan/...`, `/ban-si/...`). URL is the source of truth for catalog filters/sort/page.
- **i18n:** `next-intl` with locale `vi` default; all UI strings in `messages/vi.json` (storefront) and `messages/vi.backoffice.json`; no Vietnamese literals in components, no concatenated sentences, `Intl` for VND/date (`Asia/Ho_Chi_Minh`). Adding `en` later = new catalog file + locale routing flag, no component edits. Technical identifiers, enums, API codes remain English; API error `message` is Vietnamese but UI maps by `code` → message key (so wording can change without API changes).
- **Responsive:** breakpoints `sm 681`, `md 981`, `lg 1200`; fluid below 681; verified widths 320, 375, 390, 430, 768, 1024, 1280, 1440, 1920 and 200% zoom — zero horizontal scroll. Mobile: bottom bar, filter drawer, sticky add-to-cart on PDP; 44 px tap targets; min body 14 px (prototype's 9–11 px text raised).
- **Accessibility:** landmarks, heading order, visible focus ring (`#7edc99` outline from prototype), labelled inputs + inline errors (`aria-describedby`), `aria-live` for toasts/cart updates, keyboard-complete flows, `prefers-reduced-motion` for slider; images with alt (illustrative ones: "Ảnh minh họa …").
- **States:** every route implements loading (skeleton), empty, error (retry), unauthorized (redirect to `/dang-nhap?next=`), offline banner. Checkout: disable submit on first click, generate `Idempotency-Key` once per attempt (stored in memory + sessionStorage keyed by quote id, reused on retry), show success only after 201.
- **SEO:** indexable only ACTIVE products/categories (`robots`, `sitemap.xml` generated from API), canonical, OG, JSON-LD `Product/Offer` only when real price+availability exist; no fake ratings.
- **Auth in browser:** HttpOnly cookies set by API; Next middleware only does UX redirects (API is the authority). Client storage limited to UI prefs.
- **Backoffice:** same stack, dense table UI (TanStack Table), permission-aware actions from `/v1/me/permissions`, confirm dialogs for destructive/financial actions with reason capture; factory portal mobile-first, large touch targets.
