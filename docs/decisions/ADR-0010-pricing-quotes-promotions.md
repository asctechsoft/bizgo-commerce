# ADR-0010 — Pricing, tiers, checkout quote, promotions, margin guard

**Status:** Proposed · **Sources:** BRD §04/§4.1, Spec §04/§07 · **Blocked:** D04, D05, D08, D14, D17

## Decision

- `price_lists(id, channel RETAIL|WHOLESALE, name, status)` + `price_rules(price_list_id, variant_id, tier_id NULL, min_qty, unit_price_vnd, effective_from, effective_to NULL, priority, currency='VND')`. Resolution for an actor/variant/qty at `now`: filter active window → channel/tier of the actor (retail for guests/unapproved) → highest `min_qty ≤ qty` → highest `priority`. **DB exclusion constraint** (`btree_gist`) forbids overlapping windows for same `(price_list, variant, tier, min_qty)`; tie-break deterministic otherwise.
- `supplier_costs(variant_id, supplier_id, cost_vnd, valid_from, valid_to)` — permission `cost:read/write` (OWNER, ACCOUNTANT) only; separate table, never joined by public/factory code paths (ADR-0008).
- **Quote calculation** (pure, unit-tested `PricingEngine`): lines → unit price (server) → promotions (stackable rules; cap total discount; percent via bps, allocation largest-remainder per ADR-0003) → shipping (from `ShippingQuoteProvider`; if none/undecided ⇒ `shippingFeeVnd=null` + blocker `SHIPPING_FEE_UNDETERMINED`) → tax (`UNDETERMINED` ⇒ blocker `TAX_POLICY_UNDETERMINED`) → totals. Returns `canPlaceOrder` + `blockers[]` (`SKU_NOT_READY, PRICE_NOT_SET, OUT_OF_STOCK, DELIVERY_UNSUPPORTED, BELOW_MIN_ORDER, ABOVE_MAX_WEIGHT, STORAGE_CLASS_CONFLICT, …`). No blocker may be bypassed by the client.
- **Margin guard:** expected contribution margin per BRD §4.1 formula (revenue net + shipping collected − supplier cost − packaging − shipping borne − payment/COD fees − promo borne − allocated costs). If below configured `min_margin` (D04) ⇒ discount requires an approval (`discount_approvals`, OWNER/limit-holders) — the margin computation lives only in the finance module and is **never** in customer/factory DTOs.
- **Promotions:** `promotions(code, rules jsonb validated by schema, channel/tier/sku scopes, max_redemptions, per_customer_limit, valid window)` + `promotion_redemptions` unique `(promotion_id, order_id)`; redemption counter incremented in the order transaction with a conditional UPDATE (no oversell of coupons).
- **B2B tiers:** price visibility only through the organization's `customer_tier` after approval (ADR-0008). Large/variable quantity ⇒ Quote flow (`quotes`, ADR-0005) with expiry; quote acceptance creates an order from the **immutable quote snapshot**, then revalidates stock only (price fixed until `expires_at`).
- **Order financial snapshot** `order_financials` written at order create: revenue, discounts, tax (null if undetermined), shipping charged, **cost snapshot**, packaging, fees, expected margin. Actual margin is updated only by settlement events (never rewrites the expected snapshot).
