# ADR-0014 — Testing strategy

**Status:** Proposed · **Sources:** CLAUDE.md ("Tests are mandatory"), Spec §11–§12 (18 UAT cases), Arch §13

| Layer                                   | Tooling                                                                                                                                           | Rules                                                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Unit (pure)                             | Vitest                                                                                                                                            | money allocation, unit conversion, pricing engine, transition tables, SKU gate, error mapping                    |
| Integration (API + **real PostgreSQL**) | Jest/Vitest + Supertest + `embedded-postgres` locally, service container in CI                                                                    | no SQLite/mocks for orders, stock, idempotency, outbox; each test file gets a fresh schema via template DB clone |
| Concurrency                             | Same harness, `Promise.all` of N parallel HTTP calls + direct SQL races                                                                           | stock=1 two buyers; stock=K N buyers; cancel vs dispatch; expiry vs verify; duplicate idempotency key            |
| Contract                                | OpenAPI diff in CI; generated client type-checks in web apps                                                                                      |                                                                                                                  |
| Security/permission                     | table-driven (role × endpoint × resource-owner) matrix test generated from `PERMISSION_MATRIX`; factory JSON key-scan; rate-limit/OTP brute-force |                                                                                                                  |
| Webhook                                 | signed fixtures, replay, wrong amount quarantine, out-of-order                                                                                    | (Phase 4/5)                                                                                                      |
| E2E                                     | Playwright (storefront + backoffice) on Chromium/WebKit/Firefox where feasible                                                                    | customer→admin→factory→shipment; uses `TEST-` SKUs only                                                          |
| Responsive/a11y                         | Playwright viewport matrix (320, 375, 390, 430, 768, 1024, 1280, 1440, 1920), `axe-core`, no-horizontal-scroll assertion, 200% zoom smoke         | screenshots stored per phase                                                                                     |
| Data                                    | seed test: 82/8/DRAFT/immutable source columns; migration-from-scratch test; restore drill (Phase 4)                                              |                                                                                                                  |

- **Mapping to the 18 UAT cases:** each has a test ID `UAT-01…UAT-18` (see `docs/phase0/04_REFINED_TASKS.md`); a phase may not be marked done while its mapped cases are skipped.
- **Coverage gates:** business modules (pricing, inventory, orders, payments) ≥ 90 % lines on pure logic; no gate on glue code but every endpoint has ≥1 positive and ≥1 negative test.
- **Honesty rule:** reports quote actual command output; a test skipped for environment reasons (e.g. no Docker) is listed as **NOT RUN**, never as passed.
